# TR — Truth

## Covers

Repo truth, documentation accuracy, planning honesty, benchmark publication,
and investigations that keep `git-cas` honest about what it is and how it
works.

## Who Cares

- maintainers
- contributors
- operators evaluating storage, security, and adoption tradeoffs
- coding or review agents that depend on repo truth

## Success Looks Like

Humans and agents can rely on the repo docs and planning surfaces without
discovering later that an important boundary, tradeoff, or workflow was stale.

## How We Know

- backlog and design surfaces agree
- canonical docs point to the right adjacent truths
- threat, benchmark, and architecture claims match shipped behavior
- follow-on investigative work is named instead of hand-waved
