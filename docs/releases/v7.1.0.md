# git-cas v7.1.0: durable reservation admission

This release adds `cas.reservations.open()` for applications that must reserve permanent record capacity before an irreversible effect. The implementation merged in [PR #158](https://github.com/git-stunts/git-cas/pull/158). ## Contract

A namespace has an immutable, positive safe-integer record-slot limit. `reserve()` charges one slot for an exact key and request binding. An identical retry recovers that attempt even at capacity; a different binding refuses. `prepare()` pins original evidence before acknowledging preparation. Only a freshly acknowledged `arm()` transition permits the application to execute its effect. Recovery of an armed attempt never issues a second permit.

`settle()` pins final evidence while retaining the original preparation. `cancel()` refunds only an unarmed, unsettled attempt, first recording its terminal tombstone and then removing its exact custody pin. Failed cleanup remains retryable residue. `reconcile()` repairs installed storage phases without executing or replaying application effects. `readEvidence()` returns exact original or final pages; bounded listing binds its cursor to one immutable ledger snapshot and phase filter.

Record-slot capacity is not a physical-byte quota. Evidence pages are at most 16 MiB, with at most 64 blob/tree support roots and 63 caller-supplied commit parents. Listing returns at most 100 records and visits at most 8,192 index nodes per call. A cursor is not a retention pin; GC can make an old listing snapshot unavailable. No cross-ref atomic snapshot, TTL reclamation, application authorization or physical power-loss guarantee is supplied.

## Compatibility

The API is additive to v7.0.0. Existing assets, caches, encryption, handles and refs keep their contracts. New reservation namespaces use `refs/cas/reservations/*` and `refs/cas/reservation-custody/*`. New content manifests carry producing-package `formatVersion: "7.1.0"`; this remains separate from the manifest schema version. Zod 4 and published Plumbing `^3.3.3` remain required.

Deno CI and release commands now install the frozen pnpm project graph and execute with `--node-modules-dir=manual`. This removes fresh Deno transitive resolution from those paths without changing dependency ranges. The separate unlocked Bun image-install follow-up remains [#161](https://github.com/git-stunts/git-cas/issues/161).
