# git-cas v7.2.0: path-compressed reservation index

This release makes each reservation ledger update write about log16(records) index trees instead of 64. The change merged in [PR #168](https://github.com/git-stunts/git-cas/pull/168) for [#167](https://github.com/git-stunts/git-cas/issues/167). [Issue #169](https://github.com/git-stunts/git-cas/issues/169) records the release gates and publication. Signed tag `v7.2.0`, npm gitHead and the successful [release workflow](https://github.com/git-stunts/git-cas/actions/runs/42249242979) identify source `3008b4a17603c44e0cf191e37f65db6f79409be3`. The [GitHub Release](https://github.com/git-stunts/git-cas/releases/tag/v7.2.0) is published.

## Change

The reservation index was a 16-way trie with one tree per hex digit of a key's 64-digit route, so every record sat 64 trees deep and every update rewrote all 64. A record now sits at the shortest route prefix no other record shares. Inserting a key that meets another key's record pushes both down to the first digit where their routes differ. Sixty-four levels remain the worst case, so the documented listing and node bounds are unchanged.

Measured in a native repository after 400 prior records, one `reserve` wrote 68 objects under 7.1.0 and writes 7 under this release, in both SHA-1 and SHA-256 stores (`test/integration/reservation-index-cost.test.js`).

## Compatibility

The public API is unchanged. An index written by 7.1.0 places every record at full depth, which is a valid uncompressed trie: it reads, updates and lists without migration, and new keys branch off early.

git-cas 7.1.0 refuses an index written by this release as `RESERVATION_CORRUPT` on read, list and recovery. The failure is loud rather than silent, but every process that reads or writes a clone's reservation ledger must upgrade together, and downgrading after 7.2.0 has written a ledger is not supported.

## Evidence

All 14 release steps passed on merged main in Docker: lint, 2,416 unit tests on Node and Bun and 2,407 on Deno (12 runtime-specific skips), the three examples, public type compatibility, 353 integration tests on each runtime, the build stamp, npm pack and the JSR dry-run. PR #168 also had an independent correctness review, whose probe of insertion-order independence, final-digit splits and paging across a later split passed.

git-warp installed the published artifact by its registry integrity and passed 333 custody and `Warp` tests. A retained `Warp` write there measured 53 loose objects over 100 writes, down from about 301 on 7.1.0 ([git-stunts/git-warp#1080](https://github.com/git-stunts/git-warp/issues/1080)).
