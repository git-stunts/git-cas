# git-cas v7.0.0 Security Release Candidate

This candidate migrates the public schema entrypoint to Zod 4. It is a major release because consumers composing exported schemas must use Zod 4, schema generic annotations change, and integer validation rejects values above the JavaScript safe-integer limit. See [UPGRADING.md](../../UPGRADING.md#v6512-to-v700-candidate) before adopting it.

## Observable changes

The `@git-stunts/git-cas/schema` entrypoint retains its exported schema names. Its schema objects and generic declarations now belong to Zod 4. The new strict schema fixture checks the declarations without skipping dependency diagnostics and distinguishes defaulted output fields from optional inputs.

Stored or externally supplied metadata above `Number.MAX_SAFE_INTEGER` is refused on read and write. There is no automatic migration or legacy parsing fallback. Custom schema messages remain, while default Zod diagnostics and union error text can change. A shared application `z.config(...)` can affect default messages. The migration guide identifies affected fields and callers.

## Scope

No package split, CLI relocation, stored object-format rewrite, ref rename, or encryption algorithm change is included. The unfinished Cleave workspace split remains a separate [v8.0.0 release plan](https://github.com/git-stunts/git-cas/milestone/6). Compatible metadata and existing application handles keep their established encoding and identity; unsafe integer metadata is the explicit compatibility exception.

## Manifest version metadata

New manifests carry `formatVersion: "7.0.0"` through the existing package-version stamp. This field records the producing package version; it is separate from the manifest schema's `version` field, which remains 1 or 2. The existing parser accepts three numeric components and does not dispatch on the package major version. A prerelease suffix is rejected, so this release uses a stable version rather than changing stored-format validation to accommodate a prerelease.

A bounded real-Git witness installed published 6.5.12 and the packed v7 candidate separately, then stored, read, restored and verified a 3,840-byte plaintext file in both directions. Each reader preserved the producer's formatVersion and returned identical payload bytes. This supports ordinary plaintext compatibility; it does not establish every encryption or retention scenario, nor acceptance of unsafe integer metadata.

## Dependency and verification gates

This candidate requires published Plumbing `^3.3.3`. The refreshed lockfile contains Zod 4 throughout the production dependency tree, and its production audit reports zero findings. The final release must pass the documented Node, Bun-launcher and Deno checks, both public type fixtures, maintained examples, package checks and JSR dry-run under the repository's bounded Docker workflow. The developer dependency audit is a separate boundary.

Issue [#151](https://github.com/git-stunts/git-cas/issues/151) and PR [#152](https://github.com/git-stunts/git-cas/pull/152) own the migration. [#154](https://github.com/git-stunts/git-cas/issues/154) owns dependency adoption, release verification, publication and a fresh registry consumer. The unrelated full-public-declaration export repair remains [#153](https://github.com/git-stunts/git-cas/issues/153).

This candidate document claims no published 7.0.0 artifact. Merge approval, an immutable tag, successful publication and registry-consumer evidence remain required. Candidate preparation does not establish that downstream git-warp has adopted this release.
