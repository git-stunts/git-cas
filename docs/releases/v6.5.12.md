# git-cas v6.5.12 Release Notes

This patch release bounds object-metadata requests. `readObjectInfos` splits uncached targets into ordered windows of at most 1000 objects and 64 KiB of encoded cat-file commands, including SHA-256 object names, for both the persistent cat-file session and the command fallback. Root-set admission validates targets in bounded windows before any root-set object is written.

Root sets with more than 1000 targets (936 for SHA-256) previously failed admission with `ROOT_SET_TARGET_UNREADABLE`, caused by Plumbing's cat-file batch limit. Downstream, git-warp checkpoints failed with "Workspace staged an object but could not establish retention" near 1600 live nodes ([git-warp#958](https://github.com/git-stunts/git-warp/issues/958)).

## Compatibility

No API, handle, stored object, descriptor, ref namespace, encryption, or reader format changes. Plumbing's request limits are unchanged and target validation is not bypassed. Request order, duplicate results, cache hits, and per-target failures are preserved; a missing or mismatched target in any window still blocks publication.

## Evidence And Delivery

Issue [#147](https://github.com/git-stunts/git-cas/issues/147) and PR [#148](https://github.com/git-stunts/git-cas/pull/148) own delivery. The window witnesses fail 18 cases against v6.5.11, including real SHA-256 repositories at 999 targets, and pass on the candidate across Node, Bun, and Deno. Full release verification, merge, tag, npm publication and registry consumer evidence remain required; this candidate document claims no published 6.5.12 artifact.
